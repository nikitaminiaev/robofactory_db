# Документация по копированию модулей с версионированием и Git интеграцией

## Обзор

Система поддерживает копирование модулей с автоматическим версионированием и интеграцией с Git для отслеживания изменений в BREP файлах.

## Копирование модуля

### API Endpoint

```
POST /api/modules/{module_id}/copy
```

### Параметры запроса

- `new_author` (string): Автор копии модуля
- `version_number` (string): Номер версии для новой копии
- `description` (string): Описание изменений в версии

### Пример запроса

```json
{
  "new_author": "Иванов И.И.",
  "version_number": "1.1",
  "description": "Обновленная версия с новыми функциями"
}
```

### Что происходит при копировании

1. Создается новая копия модуля с указанным автором
2. Копируются все связи parent-child с ролями
3. Копируется bounding_contour (если существует)
4. Инициализируется Git репозиторий для нового модуля
5. Создается коммит с копированными файлами
6. Сохраняется информация о версии в базе данных

## Сохранение BREP файлов

### API Endpoint

```
POST /api/modules/{module_id}/brep
```

### Параметры запроса

- `file` (multipart/form-data): BREP файл
- `filename` (string, опционально): Имя файла (по умолчанию берется из загруженного файла)

### Пример использования

```bash
curl -X POST "http://localhost:8000/api/modules/123e4567-e89b-12d3-a456-426614174000/brep" \
  -F "file=@model.brep" \
  -F "filename=model_v2.brep"
```

### Что происходит при сохранении

1. Файл сохраняется в директорию `api/resources/brep_files/{module_id}/`
2. Обновляется поле `brep_files` в `bounding_contour` модуля
3. Выполняется Git коммит с сообщением "Add BREP file: {filename}"
4. Создается новая версия модуля с хешем коммита

## Версионирование

### Просмотр версий модуля

```
GET /api/modules/{module_id}/versions
```

Возвращает список всех версий модуля.

```
GET /api/modules/{module_id}/versions/latest
```

Возвращает последнюю версию модуля.

### Структура версии

```json
{
  "id": "uuid",
  "module_id": "uuid",
  "version_number": "1.1",
  "commit_hash": "abc123...",
  "description": "Описание изменений",
  "git_repo_path": "/path/to/repo",
  "is_released": false,
  "created_ts": "2023-01-01T00:00:00"
}
```

## Git интеграция

### Просмотр истории коммитов

```
GET /api/modules/{module_id}/commits
```

Возвращает историю коммитов в формате:

```json
[
  {
    "hash": "abc123...",
    "message": "Add BREP file: model.brep",
    "date": "2023-01-01 00:00:00 +0000"
  }
]
```

### Пометка версии как релиза

```
PATCH /api/modules/{module_id}/versions/{version_id}/release
```

Устанавливает `is_released = true` для указанной версии.

## Структура файлов

- `api/resources/brep_files/{module_id}/`: Директория с BREP файлами модуля
- `.git/` в каждой директории модуля для версионирования файлов
- База данных хранит ссылки на файлы в поле `brep_files` модели `BoundingContour`

## Примечания

- Все BREP файлы игнорируются Git в основном репозитории (`.gitignore`)
- Каждый модуль имеет свой собственный Git репозиторий для отслеживания изменений
- Версии автоматически создаются при копировании модулей и сохранении файлов
- Git репозиторий инициализируется автоматически при первом копировании модуля
